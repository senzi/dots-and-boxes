# 价值块算法

## 1. 问题边界

输入是一个极大安全前沿：所有格子的已填边数不超过 2，并且任何合法落边都会制造至少一个三边格。

算法不模拟两位玩家，也不优化最终比分。它只完成以下工作：

1. 枚举当前局面的每条开边；
2. 对每条开边执行“吃完所有当前可得分边”的闭包；
3. 按闭包最终吃到的格子集合合并等价开边；
4. 选择总价值最小的区块；
5. 标记该块的完整价值、标准让块和控制事件；
6. 将该块从棋盘中消解，进入下一步。

## 2. 价值定义

给定无可吃边的状态 `S` 和开边 `e`：

```text
Value(S, e) = 开 e 后，反复吃掉所有可得分边，最终新增完成的格子数
```

一条已经可得分的边在后续加边后仍然可得分，所以“把所有可得分边吃完”是单调闭包。不同的吃边顺序不会让已出现的可得分边消失；最终闭包的格子集合可作为价值块标识。

当前实现把得到相同格子集合的开边合并为同一价值块，避免把同一个田或同一条链重复计数。

## 3. 从小到大消解

`enumerateValueBlocks(mask)` 返回当前所有不同的价值块，并按以下顺序排列：

1. 完整价值；
2. 区块最小格子编号；
3. 开边编号。

Bot 永远选择第一组。因此它是确定性的分析器，不受随机数影响。随机种子只影响安全前沿的生成。

## 4. 让 0 / 2 / 4

选定价值块后，算法只在该块涉及的边和格子内搜索标准 handout：

- 搜索路径只能先走可得分边；
- 在每个中间状态尝试非得分边；
- 若该边使对方的强制吃取闭包恰好为一个连通的 2 格或 4 格区域，并覆盖当前所有已暴露的三边格，则是合法留法；
- 允许让出整个块（gift == 当前块剩余格子数）：田字让 4 / 短链让 2 是合法的
  `KEEP_BY_4` / `KEEP_BY_2`，控制方开边后不完成格子即换手，对手被迫吃完闭环，
  主动权回到控制方（2026-08-01 修正，见 fixtures/20260801-block-e-tianzi-keep4.txt）；
- 多个合法留法中最大化 `已吃格数 - 让出格数`，再优先让 2；
- 没有合法 2/4 留法时记为让 0。

搜索被严格限制在当前价值块，不扫描其他未打开的大龙。默认节点上限为 30000。若达到上限，页面显示“达到节点上限”，协议中的 `exact=0`，不得把该让块结果当成已证明结论。

## 5. 主动权事件

当前只记录事件，不擅自推出胜负：

| 条件 | 代码 | 含义 |
|---|---|---|
| 价值 1 | `FORCED_FLIP` | 必然转换主动权 |
| 价值 2 | `CHALLENGE_2` | 无主动权方争夺主动权的机会 |
| 可留 2 | `KEEP_BY_2` | 控制方可以通过留 2 保持主动权 |
| 可留 4 | `KEEP_BY_4` | 控制方可以通过留 4 保持主动权 |
| 让 0 | `TAKE_ALL` | 吃光后必须打开下一块，记录一次控制奇偶事件 |

价值 2 暂不被压成“主动权必然属于谁”。这是后续控制模型需要结合当前控制方和选择权继续求解的分支。
